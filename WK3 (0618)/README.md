# TakeMeter - r/leagueoflegends
TakeMeter is a text classification system designed to categorize user posts and comments from the r/leagueoflegends community into grounded structural categories. It addresses the common pitfall of subjective "good vs. bad" metrics by tracking the intent of online gaming communities.

The dataset consists of 203 unique, manually reviewed posts split into training (70%), validation (15%), and testing (15%) groups. ## Deep-Dive Failure Analysis (DistilBERT Errors)
Looking at the confusion matrix (confusion_matrix.png), there is a clear directional pattern: the only 2 errors in the entire test set stem from the exact same boundary confusion—actual esports_discourse posts misclassified as balance_discussion. community_meta achieved a flawless 1.00 precision and recall, meaning client bugs and system behavior are perfectly separated.

### Error Example 1: The Pro Pick/Ban Strategy Meta
Post Text: "Does anyone know why FlyQuest decided to run the lane swap strategy in game 3 against Team Liquid when their bot lane had a winning matchup? It felt like they voluntarily gave up their own win condition just to mimic what LCK teams are doing, and it completely backfired on them."

True Label: esports_discourse

Predicted Label: balance_discussion

Why the Boundary is Hard: This post uses heavy in-game strategic vocabulary (lane swap strategy, winning matchup, win condition) to critique a competitive match. While the core intent is evaluating a specific pro match tournament event (esports_discourse), the vocabulary profile heavily overlaps with mechanical meta discussions. DistilBERT over-indexed on the gameplay keywords and missed the higher-level tournament framework.

Problem Type & Change Required: This is a training data distribution problem. To fix it, I need to add more diverse examples to esports_discourse that explicitly capture pro-draft analysis, pick/ban choices, and match strategy discussions. This will teach the smaller model that deep gameplay vocabulary remains esports_discourse when anchored around professional teams like FlyQuest, Team Liquid, or the LCK.

### Error Example 2: The Pro Champion Pool Discussion
Post Text: "I really hope they don't nerf Maokai support into the ground just because he's a flex pick in competitive. He feels completely fine to play against in solo queue where teams don't coordinate around his sapling vision control perfectly."

True Label: esports_discourse (Pro Build / Pro Pick Context)

Predicted Label: balance_discussion

Why the Boundary is Hard: The text directly references game balancing (nerf Maokai support, utility kit) while establishing the context around the character's status as a top-tier competitive pick. Because the text balances mechanical changes with professional relevance, a 66-million-parameter model defaults to the raw tuning label (balance_discussion), failing to capture the systemic pro-meta perspective.

Problem Type & Change Required: This is a label definition edge case. I need to explicitly supply the model with training instances where patches are evaluated purely through a pro-scene framework, thereby establishing a firmer boundary separation between local matchmaking rants and international tournament meta trends.

## Model Reflection: What Was Learned vs. Intended
My core objective was to build an evaluation model that captures the underlying discourse intent of a post—separating structural analysis from environmental observations and competitive narratives.

*What the Model Captured*: The fine-tuned model successfully moved past basic sentiment matching. It recognized that angry balance complaints do not equal community toxicity, drawing an accurate distinction between gameplay frustration and client technical stability.

*What the Model Overfit to*: Because of DistilBERT's modest parameter layout, it over-indexed on gameplay mechanisms. If a post mentioned names like FlyQuest or Team Liquid, but used phrases like win condition or matchup, the model discarded the professional scene context entirely and pulled the post toward balance_discussion. The model overfitted to the idea that tactical analysis belongs exclusively to balance tuning.

## Fine-Tuning Pipeline & Hyperparameter Rationale
I fine-tuned the standard pre-trained distilbert-base-uncased model. During initial experimentation, my model plateaued around a 36% accuracy level because my 3-epoch setup did not afford the model enough training steps over a 140-sample training slice. I increased `num_train_epochs` to 6. This expanded training exposure without causing overfitting, as I utilized load_best_model_at_end=True to track optimal validation configurations. I compressed warmup_steps down to 10. This allowed my gradient updates to utilize the peak learning rate (2e-5) immediately, preventing the model from spending the entire short run merely warming up.

## Spec Reflection
The strict Mutual Exclusivity Constraint specified in the document kept me from introducing generalized labels like "Venting." This forced me to construct strict tie-breaker protocols (like the Shaco Rule or the Pro Build Rule) that protected our training metrics from data confusion. However, the spec assumed I could evaluate performance solely through standard overall accuracy. During data curation, I realized that live data distributions flux heavily based on the competitive schedule (e.g., tournament seasons flood the feed with esports narratives). I pivoted by changing my evaluation tracking metric to Macro F1-Score inside my training loop parameters, forcing the pipeline to value class boundaries equally.

## AI Usage Disclosure
*Label Stress-Testing*: I fed my initial definitions to an LLM assistant, instructing it to generate ambiguous boundaries between balance_discussion and community_meta. It produced an example of an emotional champion rant that motivated my final Shaco Rule amendment prior to launching manual reviews.

*Annotation Pre-Labeling Strategy*: I utilized Groq's Llama-3.3-70b interface to pre-label an initial batch of 100 entries. I cross-referenced every row manually, correcting 14 misclassifications where the model tripped over sarcastic formatting. I explicitly logged this process via my dataset tracking columns to ensure data integrity.

*Error Feature Discovery*: I provided my misclassified test logs to an AI tool to isolate pattern weaknesses. It correctly highlighted that the fine-tuned model consistently misclassified posts containing both a pro-team name and raw balance statistics. This guided my final evaluation write-up.
